Final Project Guidelines

Project Overview

This final project allows you to build a practical ML application that solves real-world problems. You will select your desired project and develop a working solution.

Portfolio Building: This project is a valuable addition to your professional portfolio. When you interview with hiring managers, you can demonstrate a real working application that solves actual problems. This is much more impressive than theoretical knowledge alone.

Take it seriously! A well-executed project can help you stand out in job interviews and show employers that you can build practical solutions with modern AI tools.

Academic Integrity

Projects having any degree of similarity with work by any other group, or with any other document (e.g., found online) are considered plagiarism and will not be accepted. The minimal consequence is that all group members will receive a project score of 0, and the best possible overall course grade will be C. Additional consequences are described at https://osccr.sites.northeastern.edu/academic-integrity-policy/Links to an external site.

All work in your project, including text, figures, analysis, code, and results, must be your original work.

Using AI Tools for Development

Highly Recommended: Use Large Language Models (LLMs) like Claude to help you build your project faster and better.

  • NEU Students: Use your NEU account to access Claude's premium features for free
  • Why use LLM: These tools can help you write code, fix bugs, explain concepts, and suggest improvements
  • Real-world skill: Learning to work with AI tools is important because this is how modern developers work

Note: Since LLMs can help with almost any task, these projects are chosen based on current trends and what people actually build with AI assistance.

Cost and API Limits

As you work on your project, please keep the following in mind:

  • Some APIs have daily request limits
  • Educational accounts often have higher limits
  • Plan your testing to stay within free tier limits

Grading Criteria

Your project will be evaluated on:

  1. Functionality: Does it work as intended?
  2. Creativity: Did you add unique features or improvements?
  3. Use Cases: Is it useful? Does it solve real problems?

Here are some examples of past student projects. These are for inspiration purposes only and are not mandatory choices.

1. Restaurant Menu Photo Matcher

Input/Output:

  • Input: Menu item name or description
  • Output: Real customer photos of that dish

2. Fashion Trend Predictor from Street Photos

Input/Output:

  • Input: Collection of street fashion photos
  • Output: Trend report with predictions and visualizations

3. Skill Swap Matcher for Communities

Input/Output:

  • Input: Single sentence from user (e.g., "I can teach cooking" or "I want to learn Spanish")
  • Output: Matched partner, scheduled 15-min intro call, then recurring session schedule

4. Medication Interaction Checker from Cabinet Photos

Input/Output:

  • Input: Photos of medicine bottles
  • Output: Safety report with interaction warnings

5. Digital Legacy Voice Companion

Input/Output:

  • Input: Voice recordings, photos, written memories, personal stories
  • Output: Interactive AI companion that speaks and responds like the person

6. Personal Finance Tracker with Insights

Input/Output:

  • Input: Transaction descriptions or CSV bank statements
  • Output: Categorized expenses, spending trends, and saving tips

7. Salary Optimization Advisor

Input/Output:

  • Input: Current salary, resume, job title, location
  • Output: Detailed report with salary comparison and action steps

Project Deliverables

(100 Points) Project Proposal - Due June 28

Each group (2 or 3 members) will prepare a written proposal, which should not exceed 1 page, 11 points font single-spaced. Appendices are allowed but will be reviewed at the instructor's discretion.

Format: Submit as PDF (no Word documents)

Required Sections:

  1. Authors: List all group members, expected degree, and year in program
  2. Problem Description: 1-2 paragraphs describing the chosen project and the specific question you'd like to answer
  3. Data Summary: 1-2 paragraphs describing the dataset or inputs your project will use
  4. Methods: 1-2 paragraphs describing implementation approach and potential challenges
  5. Preliminary Results: Brief description of any initial exploration or setup completed
  6. References: Only include references explicitly used in the text with consistent formatting

Note: A single submission per group is sufficient.

(100 Points) Project Pre-recorded Presentation - Due July 26

Record a 5 ± 1 minute presentation on Zoom or similar application. Upload as MP4 or MOV file directly to Canvas.

Required Components (evaluated equally):

  1. Introduction: Why is this problem important? What real-world need does it address?
  2. Related Work: Describe 1-2 similar projects or papers that inspired your approach
  3. Data & Features: How you processed inputs and set up your system
  4. Methods: Learning algorithms or AI models used
  5. Results: What you learned and what your application can do
  6. Demo: Show your working application

Presentation Style:

  • Make eye contact with the camera/audience
  • Have an engaging presentation manner
  • Do not read your slides
  • Jump right into content (don't say "I will introduce...")

Academic Honesty: All work must be original. Copying figures or analyses from other sources is not allowed unless properly cited.

Note: A single submission per group is sufficient.

(100 Points) Project Report - Due July 26

Written report formatted as a scientific paper, maximum 8 pages (11 pt font, single-spaced), excluding references and appendices.

Format: Submit as PDF (no Word documents)

Required Sections:

  1. Authors: Names of all group members

  2. Introduction:

    • Background of the problem and why it's important
    • Non-technical summary of your solution

  3. Methods:

    • Describe your implementation approach
    • Include technical details of AI models, APIs, and algorithms used

  4. Dataset/Inputs:

    • Describe your data sources or user inputs
    • How data is processed and used in your application
    • Cite all data sources

  5. Results:

    • Show your working application with screenshots or figures
    • Demonstrate key functionality
    • Keep description concise

  6. Discussion:

    • Compare with existing solutions or state-of-the-art approaches
    • What worked well and what challenges did you face?
    • What did you learn from this project?
    • How could the application be improved in the future?

  7. AI Prompts Used (REQUIRED if used):

    • Include ALL prompts used with Claude or other AI tools
    • Document prompts for: coding, debugging, explanations, research
    • This section is mandatory for grading

  8. References:

    • Only include references explicitly used in the text
    • Cite all data sources and APIs
    • Use consistent formatting (e.g., [1] Author. Title. Conference/Journal, Year.)

  9. Appendix:

    • Link to public GitHub repository with code
    • Additional plots or technical details
    • Installation and setup instructions

  10. Statement of Contributions:

    • For groups of 2-3: describe each member's contributions
    • Not required for solo projects
    • Does not count toward page limit

Code Repository:

  • Must include link to public GitHub repository
  • If code cannot be made public, submit as zip file on Canvas

Writing Standards:

  • Formal academic writing (no slang or jargon)
  • No spelling or grammar mistakes
  • All claims must be supported by citations, results, or common knowledge

Note: A single submission per group is sufficient.

Tips for Success

  1. Start simple: Build the basic version first, then add features
  2. Test frequently: Use free API limits wisely by testing as you build
  3. Save your prompts: Keep a document with ALL AI prompts you use - required for grading
  4. Document everything: Write down challenges and solutions as you work
  5. Communicate with instructor: Discuss your project early if you have questions

Important Notes

  • Plan to form a group of 2 or 3 early.
  • Each group works independently
  • You are welcome to discuss technical issues with others, but all work must be original
